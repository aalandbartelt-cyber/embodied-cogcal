## 运行器关键差异

- `rollout_e8.py` 的 `--tag e8` 绑定旧 12850–12869；`smoke` 最多两集，不能把新正式运行标为 smoke 或沿用 E8 预注册 hash。当前合同 `kind=e8_rgb_theta_estimator_not_method`、`prereg_sha256`、`source_sha256` 均硬编码旧 E8 文件，必须改为本实验的真实身份、冻结协议与实际执行源哈希。
- 对每个 seed 的 `delta_mm_for(-15,1,seed)` 相同，名义上可配对；但须在实际执行中核验 reset 后对象姿态、源目标位置、随机状态和物理参数等，不能只比 seed 和 delta。policy worker 的 reset 仅响应 `{"reset":true}`，须审计其随机性；如有随机采样，应为每个 seed/臂设置同一随机状态并记录。
- `fixed` 路径仍运行 RGB 估计器，遇到 |估计−真值|>5° 会抛错；不应默默删去这一准入条件或只丢弃失败臂。要么明确按相同规则固定并独立报告失效，要么在冻结前将纯固定剂量路径与估计解耦，验证其他语义未变。
- `args.out` 与 `args.physics` 必须不存在；逐集排他创建轨迹、先写 contract，因此异常后的断点续跑目前没有安全实现。不能直接覆盖或重跑部分臂。需新建尝试目录、记录作业中断、验证已有完整产物并用不覆盖策略恢复；无法证明同一实验契约则整组标记无效。
- `task_success` 来自 carrier 的 `outcome()`，当前读取的是字节码。确认其定义和有效性，记录其载体 hash 及固定阈值，并确保终点来自同一版本；验证器检查完整配对、输入、330 步、各期望结果和 physics hash。若不能核查源代码或行为，则必须披露并禁止做超过可验证范围的主张。

## 最小独立实现与验收顺序

1. 先复核草稿科学假设、预算、时间/磁盘及 seed 来源；在不修改旧文件前提下创建新 runner，固定 −15°、四个剂量与正式及 smoke seed 列表，正式程序默认拒绝运行，只有存在经核验的不可变冻结清单时可启用。不同臂均使用固定剂量路径，合同记录本协议和真实源代码 hash。
2. 运行前建立有可复现随机化策略的不可覆盖执行计划；采用单 seed 四臂独立运行或等价调度，避免资源变化系统性偏向单臂。记录每次启动和恢复；若中途停止不得基于表现修改顺序、样本或终点。
3. 不调用 MuJoCo 的单元测试覆盖：拒绝已存在输出、拒绝未冻结/错误 hash、种子不重叠、剂量顺序完整、重复/缺失配对检测、按配对计算 McNemar、极端无分歧情况及 bootstrap 可重复性。核查合同中的 protocol/source/checkpoint hash。
4. 实施与运行器分离的跨臂验证器，验证 reset、物理设置、轨迹条数、成功谓词、完整性和录入一致性；之后只在独立 smoke seed 做环境验证。smoke 是实验前检查，不计入正式样本；冻结条件全部满足后才可启动正式运行。

实施前尚需修订协议中执行顺序的具体固定算法与可验证阈值、确认从 checkpoint 可恢复的策略以及资源硬上限；当前草稿和 E8 本身都不能保证跨臂 reset/随机状态完全相同。

## 补充：来源、随机性及已有结果离线核验

- carrier `outcome` 字节码可用 Python 3.12 `marshal` 与 `dis` 审计。它计算 placed=终点 xy 距离 ≤35 mm 且 z 距 14 mm ≤12 mm；released=结尾连续无机器人接触 ≥0.1 s；held=双指接触且高度相对源高 >50 mm 的最长持续时间 ≥0.5 s；穿透 ≤1.5 mm；task_success 是四者合取。与既有报告口径相符。但字节码出处对应的原始源码缺失，且无法仅由摘要验证早先每次接触采集完全正确。
- `reset(seed)` 字节码以 `np.random.default_rng(seed)` 产生 xy 两个 ±5 mm 随机偏移，重置 MuJoCo 数据及计数；E8 `delta_mm_for` 另外以 yaw 和 seed 确定每轴偏移。实际还要核对对应观测、完整模型状态、执行前 RNG 状态，才能证明所有随机输入的配对。
- `official-act-20261116/infer_worker.py` 调用 `model.eval()`、`torch.inference_mode()`；收到 reset 仅调用 `model.reset()`，没有显式设置 RNG 种子或开启 GPU 确定性算法。模型评估模式虽减少常见随机源，但不能仅凭源码保证 GPU 精确复现或证明随机性已经配对；需复核库模型实现及同输入重复实验，在正式运行前记录软件/GPU 信息并做确定性测试。不得假定 bitwise 一致。
- 既有 `runs/nocomp-15`、`runs/diag-15-neg7p5`、`runs/est-15` 共 60 条已有记录，新增只读脚本 `audit_e8_paired_offline.py` 可用 cogcal-sim Python 从仓库根执行；实际运行 PASS，核对每条 330 step、trace/physics SHA-256、源/目标与 delta、同 seed 初始 q 和 RGB hash；由逐 tick 物理记录重算最终位置、最长双指抬升、尾部无接触释放、最大穿透以及聚合终点。这只证明已有输出内部一致，非原始接触记录完全独立的测量，也不证明隐藏 RNG 状态配对，不能证明新运行等价。
