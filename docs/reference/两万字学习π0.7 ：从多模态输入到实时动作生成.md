## **如何阅读这张推理图**

可以把这张图理解为五个并行运行的时钟。两条蓝色通道代表硬件：

- **Motors**：执行动作；
- **Sensors**：读取相机和关节状态。

三条白色通道代表模型：

- **low-level VLM**：也就是 π0.7 本身，将观测转换为机器人动作；
- **high-level VLM**：以文本形式写出下一个子任务；
- **BAGEL World Model**：绘制完成该子任务后场景应该呈现的图像。

黄色标签表示时间。 ms 表示第一个动作开始执行的时刻。

绿色模块读取传感器，粉色模块运行模型，灰色模块执行动作。绿色箭头表示数据从一条通道传递到另一条通道。

启动之后，三个模型运行在相互独立的线程中，不会彼此等待。每个模型都会使用其他模型当前已经产生的最新输出。因此，速度较慢的 World Model BAGEL 不会阻塞机器人运行。

左侧的三维视图会在两台 SO-101 机械臂上重放每个时间块。系统配置包括一个顶部相机和两个腕部相机，这也是该项目所针对的硬件结构。真实推理只需要几毫秒，但三维视图会将过程放慢并夸大动作幅度，使每一步都更容易观察。页面中的动作是预先编写的，浏览器中不会实际运行模型。可以使用键盘上的 ← 和 →，或者页面上的按钮，在不同模块之间切换。若不进行操作，演示会自动播放并循环；每次循环都会让机器人继续执行后续两个子任务。

## **1. 启动：读取传感器**

在机器人开始运动之前，系统首先收集初始观测。

### **相机帧**

每个相机提供一张图像，并被缩放为 像素。当前硬件配置包含三个相机：

- 安装在龙门架上的顶部相机，对应论文中的前置相机；
- 安装在左侧机械臂腕部的相机；
- 安装在右侧机械臂腕部的相机。

### **Proprioception**

系统读取两台机械臂当前的关节位置。每台 SO-101 机械臂包含五个关节和一个夹爪。

### **metadata**

metadata不是传感器直接测量得到的，而是由操作员设置。在运行时，论文始终要求模型采用训练数据中观察到的最佳行为：

- 质量等级为 5；
- 没有发生错误；
- 速度设置为该任务所有 episode 时长的第 15 百分位。

控制模式也在这里设定，可以选择 joint control 或 end-effector control。

在正常运行过程中，π0.7 还会读取每个相机最多五张历史帧。历史帧之间间隔 1 秒，并且每张图像都对应相匹配的关节状态。启动阶段还没有历史信息，模型需要能够处理这种情况。训练时，30% 的样本会完整移除历史信息，以提高模型在缺少历史观测时的适应能力。

- 一次包含元数据；
- 一次不包含元数据。

然后，模型将结果沿着元数据所指定的方向进一步推动。这种方法称为 **classifier-free guidance**。对于 dexterous manipulation 任务，论文使用的 guidance strength 为 1.3 到 2.2。

## **6. 执行动作 到** 



![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kltic3d4ibvZ97jA5zHOCGLZ1fGJA1ZLGAqbEBw6ct4gUl2ACQKobuKj8b85GWpib5s7at1f9x4q0UYbXsum6fFkTjxyAHHVgmUoaSjfbhsChE/640?wx_fmt=png&from=appmsg)

机器人每隔 20 ms 执行 action chunk 中的一个动作，而不会在每一步重新请求模型推理。

π0.7 实际只执行 50 个动作中的前 15 个或前 25 个动作。该演示采用 15 个动作，因此：



动作 到 总共执行 300 ms。

如果完整执行整个 action chunk，机器人实际上执行的将是一秒之前制定的计划。另一方面，如果每个动作都重新请求模型推理，也无法满足实时要求，因为一次推理耗时超过 20 ms。

因此，系统执行 15 个动作后重新规划。这种方式在动作连续性和实时响应之间取得平衡。

训练阶段，π0.7 已经学习过这种情况：模型会接收一个 action chunk 开头的 0 到 12 个无噪声动作，然后学习如何在此基础上继续生成后续动作。

## **10. 切换到第二个 action chunk**



第二个 action chunk 到达时，它是根据 300 ms 时刻获取的观测规划出来的。因此，它的前几个动作描述的是已经发生的时间点。

在第二个 chunk 计算期间，机器人已经按照第一个 chunk 执行了这些动作。因此，执行过程不会从第二个 chunk 的第一个动作重新开始，而是直接跳转到与当前时间相匹配的位置。

在图中，这一位置被标记为第二个 chunk 的第 6 个动作 ：

“它已经落后了 6 个动作，因此执行第 6 个动作，而不是第 1 个动作。”

由于 real-time chunking 要求新 chunk 从机器人实际已经执行的动作开始，因此两个 chunk 之间可以平滑衔接。

从此以后，系统不断重复以下循环：

执行动作 → 获取观测 → 在后台计算下一个 chunk → 切换到新 chunk。

## **π0.7 的整体结构**

π0.7 是 Physical Intelligence 于 2026 年发布的机器人控制模型，拥有约 50 亿参数。它读取相机图像、机器人关节位置和文本 prompt，然后输出机器人接下来要执行的 50 个动作。这类模型被称为 VLA，即 Vision-Language-Action model。

这篇论文最重要的设计是 prompt。

π0、π0.5 和 π0.6 等早期模型通常只接收简短的任务描述。π0.7 除了任务描述之外，还使用当前子任务指令、episode metadata、控制模式，以及部分样本中“几秒之后场景应该呈现的图像”。

episode metadata 包括：

- 机器人执行任务的速度；
- 执行质量；
- 是否发生错误。

这些标签让同一个模型可以从不同质量的数据中学习，包括失败的 episode、自主 rollout 和人类视频，而不必把高质量行为和低质量行为简单平均。运行时，用户可以通过改变 prompt 中的内容来引导模型。

运行时有三个模型共同工作。

### **high-level policy**

### **World Model**

World Model 是一个拥有 140 亿参数的图像生成模型，初始化自 ByteDance 的 BAGEL。它根据当前子任务生成目标图像，描述完成该子任务之后场景应该呈现的状态。

页面顶部的框图只展示 low-level policy：

1. 接收多模态 context；
2. 使用 Gemma 3 backbone 对 context 进行编码；
3. 将编码结果传递给 Action Expert；
4. 由 Action Expert 生成动作。

## **Flow-matching model**



![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kltic3d4ibvZ8wHDianN70bmRzQlFRKiaW65jQO2nIkdticiaOrFiccEC2aJ7n1EMbe3s46nJkxmeicdI2EasyRSz6ff2BFgZksiaW7TqfmCx0l83OyQ/640?wx_fmt=png&from=appmsg)

系统在这里接入一个最初未经训练的 8.6 亿参数 Action Expert。

Action Expert 一次性生成完整的 action chunk，即接下来的 50 个动作。

它使用 Flow Matching 进行训练。对于一个训练样本，系统先取真实动作 chunk ，再按照比例 将它与 Gaussian noise 混合，并要求 Action Expert 判断，从当前混合状态返回数据分布应该沿哪个方向运动。

运行时，Action Expert 从纯噪声开始，沿着自己预测的方向经过 5 个步骤，得到干净的 action chunk。

使用 Flow Matching，而不是直接预测一个固定答案，是因为完成同一个任务通常存在多种正确动作。如果模型被训练去预测这些动作的平均值，最终生成的轨迹可能不符合其中任何一种真实动作。像图像生成模型一样生成一个样本，可以避免这个问题。

π0.7 还针对 real-time chunking 进行训练。机器人继续运动时，Action Expert 在后台计算下一段动作。模型会接收当前 action chunk 已经执行的部分，并生成与正在执行轨迹连续衔接的新 chunk。

log-softmax 的定义为：

## **World Model：绘制 subgoal images**





World Model 为当前子任务绘制 subgoal images：分别针对 front camera、left wrist camera 和 right wrist camera，生成三张图像，描述子任务完成后这些相机应该看到什么。

π0.7 会将这些图像作为 prompt 的一部分读取。

这是一个独立且更大的网络，拥有 140 亿参数，初始化自 ByteDance 的 BAGEL。BAGEL 是一个用于图像理解、编辑和生成的开源模型。

World Model 的输入包括：

- 当前图像；
- 子任务文本；
- episode metadata。

它通过 Flow Matching 生成三张目标图像。

之所以使用独立模型，是为了实现知识迁移。

BAGEL 预训练于 web-scale 图像和视频，World Model 还会进一步使用以下数据进行训练：

- 机器人数据；
- 人类第一人称视频；
- 开源图像编辑数据；
- 视频数据。

因此，它能够想象机器人数据中从未出现过的场景。

Subgoal images 将这些知识传递给 π0.7：

- 有了 subgoal images 后，π0.7 能够更可靠地执行不常见的指令；
- 在论文的“Reverse Fridge to Microwave”任务中，subgoal images 起到了关键作用；
- 对于训练数据中没有折叠任务的机器人，subgoal images 也提高了 zero-shot 毛巾折叠和衬衫折叠的效果。

## **Mixture of transformers**

BAGEL 是一个 mixture of transformers。

BAGEL 初始化自 Qwen2.5 7B language model。

它包含两个拥有 70 亿参数的 Transformer，并在每一层共享一次 self-attention operation。这种安排与 π0.7 中 VLM backbone 和 Action Expert 的结构类似。

### **Understanding transformer**

Understanding transformer 处理：

- 文本；
- ViT token。

### **Generation transformer**

Generation transformer 处理：

- VAE token。

每个 token 只会经过其中一个 Transformer。因此，总参数量为 140 亿，但对于单个 token 来说，大约只有 70 亿参数处于 active 状态。

## **Flow-matching loss on images**

World Model 使用目标图像上的 Flow Matching 进行训练。

三张目标图像的 VAE token 会与噪声混合。Generation transformer 根据带噪声的 token，预测从噪声状态回到干净目标图像的 velocity。

随后，模型预测的 velocity 与真实 velocity 之间使用 squared error 进行比较。

这与 EAM Loss 的思想相同，只是生成对象从动作 token 换成了图像 token。

生成过程以以下信息为条件：

- 当前图像；
- 子任务；
- episode metadata。

由于每张目标图像都是同一 episode 中更晚时间点的真实帧，World Model 可以从机器人自身相机记录的画面中学习“子任务进展完成后应该是什么样子”。

## **Inference、refresh 与使用生成目标训练 π0.7**

运行时，World Model 与 π0.7 并行运行，而不是位于 π0.7 前面，形成必须等待的串行模块。

### **When：何时生成**

出现以下任一情况时，系统会生成一组新的 subgoal images：

- 当前子任务发生变化；
- 距离上一组 subgoal images 生成完成已经过去 4 秒。

以先发生者为准。

World Model 在独立线程中运行。新的目标图像到达之前，π0.7 会继续使用旧的 subgoal images 执行动作。

### **How：如何生成**

World Model 使用 25 个 denoising steps。

每一步都会同时对文本和图像使用 classifier-free guidance。

带 guidance 和不带 guidance 的两个版本会被打包进同一个序列中，并使用 attention mask 防止它们互相读取。

这样，一次 forward pass 就可以同时计算三张目标图像。

### **How fast：生成速度**

World Model 的序列长度接近 10000 个 token。

在 4 张 H100 GPU 上，使用以下配置：

- 4-way tensor parallelism；
- 8-bit matrix multiplication；
- 修改后的 SageAttention kernel。
