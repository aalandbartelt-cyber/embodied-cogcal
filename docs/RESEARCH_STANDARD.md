# 科研规范（教科书级）

> 适用：本仓库全部 discovery 实验，以及任何要写进论文、放进附录、被他人复用的结论。
> 定位：这是一份**可执行**的规范——每一步都有产物、有判据、有失败样例。面板的「研究路线」页签按本文第 3 节判定。

---

## 0. 三条不可让步的原则

1. **可证伪优先**：没有"什么结果会推翻它"的陈述，不是假设，是愿望。
2. **先冻结、后观察**：判据、样本量、停止规则、分析计划必须在看到结果前写进预注册；看到结果后再改，必须留下偏差记录（`DEVIATIONS.md`），并降级为探索性证据。
3. **记录只增不改**：合同、逐集记录、哈希一旦写入不得覆盖；修正以新目录 + 新 attempt 表达，历史保留。

## 1. 八步流程

### 第 1 步 问题（Question）
- 产物：`DIRECTION.md` 或实验 `PLAN.md` 中的"问题"小节。
- 判据：一句话能说清"在什么条件下、什么现象、为什么值得知道"。
- 反例：把"提升成功率"当问题——没有对象、没有条件、无法否证。

### 第 2 步 假设（Hypothesis）
- 产物：`PREREG*.md` 中的 H1…Hn，每条含**方向**与**量级**。
- 判据：每条假设都能对应一个统计量和一个决策规则。
- 反例：E7B 曾把 McNemar 的方向写反，靠偏差记录补救——方向必须逐字复核。

### 第 3 步 预注册（Preregistration）
必须冻结以下六项，缺一即视为未冻结：

| 项 | 内容 | 判据 |
|---|---|---|
| 臂与剂量 | 每个条件的参数取值 | 能用表格列出，无"待定" |
| 种子 | 新鲜、互斥、未被历史运行使用 | 附种子清单与其来源块 |
| 每臂集数 | 与功效计算一致 | 给出 α、目标效应、功效 |
| 成功判据 | 阈值、窗口、评分函数来源 | 端点定义不可在事后更改 |
| 停止规则 | 异常/故障/不完整的处理 | 与技术失败分开定义 |
| 分析计划 | 主对比、次要对齐、多重比较处理 | 明确"确认性"与"探索性"分界 |

- 冻结后写入 `prereg_sha256`，由合同引用。

### 第 4 步 执行（Execution）
- 产物：`contract.json`（身份 + 哈希）、`episodes.jsonl`（逐集一行）、`*.trace.jsonl`（逐控制步）、`physics/*.npz`（集末）。
- 判据：attempt 目录连续、每臂集数完整、无中途停止；中断必须以新 attempt 续跑，不得覆盖。
- 反例：输出目录已存在就重跑，会把旧记录与新记录混在一份文件里。

### 第 5 步 完整性验证（Integrity）
- 独立校验器（`verify_*.py`）逐项核对：哈希、配对数、步数、终点重算、物理数组范围。
- 判据：`error_count=0`，且校验器本身不依赖被测 runner 的代码路径。
- 反例：用 runner 自己算的指标证明 runner 正确。

### 第 6 步 报告（Report）
- 产物：`RESULTS*.md` + `analysis.json` + `DEVIATIONS.md`。
- 判据：结论表逐条对应假设；负结果与偏差单列；每个数字可追到文件。
- 反例：E4 曾把"注册对比是双重差分"写成因果归因；E8 曾把 `both` 的 1/20 写成"全失败"。

### 第 7 步 复现（Reproduction）
- 三层：同机重跑（哈希一致）→ 换机重跑（环境记录完整）→ 换 seed/物体（外部效度）。
- 判据：三层各自给出"成立/不成立/未验证"，不得用一层替代另一层。
- 反例：把 canonical fallback 当作"第二训练 seed 复现"。

### 第 8 步 发表（Publication）
- 产物：图表清单（文件 + 哈希 + 生成脚本）、功效与多重比较披露、局限段。
- 判据：审稿人只拿仓库就能定位到每一根柱子的来源。

## 2. 统计纪律

1. **样本量先算后跑**：给定基线成功率与目标效应，算出 n；不允许"先跑 20 个看看"。
2. **配对优先**：同 seed 跨臂比较用 McNemar 精确检验；非配对用 Fisher 精确检验。
3. **多重比较**：确认性主对比只有一个；其余标注"探索性"，并给出未校正 p 与校正后 p。
4. **效应量 > p 值**：报告差值、区间与样本量，不只报 p。
5. **端点修正即偏差**：看到端点失败后修改区间，必须在文档中写明"何时、看到什么、改了什么"。

> 本仓库的真实教训：E8 的 H1 容差在观察到 −45° 被估成 +45° 后 36 秒内由闭区间改为开区间；E4 的注册对比同时翻转外观与接触两个因素。两者都不是造假，但都必须在论文中主动披露。

## 3. 七道门禁（面板「研究路线」按此判定）

| # | 门禁 | 通过条件 | 判定方式 |
|---|---|---|---|
| 1 | 问题与假设 | 预注册含可检验假设 | 自动：文本含 H1/假设/预测 |
| 2 | 预注册 | 判据、种子、停止规则齐备 | 自动：三项关键词 |
| 3 | 执行 | 至少一个运行有逐集记录 | 自动：`episodes.jsonl` 非空 |
| 4 | 完整性 | 有独立校验工件且集数完整 | 自动：verify/analysis 存在且 observed ≥ planned |
| 5 | 结果与负结果 | 结果文档含负结果或偏差 | 自动：文本匹配 |
| 6 | 外部效度 | 第二 seed / 第二物体 / 真机有结论 | **人工**：面板标"需人工确认" |
| 7 | 论文级证据 | 图表可追溯到文件与哈希 | **人工** |

门禁只升不降：任一项失败，后续阶段不计入"已过"。人工项不会被自动判为通过。

---

## 4. 记录与哈希

- `contract.json` 必须包含：kind、臂参数、种子、模型/策略哈希、源码哈希、预注册哈希。
- 逐集行必须包含：seed、成败、失败原因、物理与轨迹哈希。
- 外置工件（NPZ、checkpoint、字节码）不入 Git，但必须有哈希与获取方式。
- 任何"重算"都必须能从记录复现；不能复现的指标不得进入论文。

---

## 5. 面板与流程的对应

| 流程步骤 | 面板位置 | 能做什么 |
|---|---|---|
| 问题/假设 | 研究路线 → 实验行 | 看到当前阶段与阻塞项 |
| 预注册 | 实验目录 / 证据链 | 打开 PREREG，核对哈希状态 |
| 执行 | 舞台 + 运行现场 | 看实时画面、进程、进度 |
| 完整性 | 证据链 | 打开 verify/analysis 工件 |
| 结果 | 实验目录 | 打开 RESULTS 与偏差记录 |
| 外部效度 | 研究路线（人工项） | 列出待补项 |
| 论文证据 | 研究路线（人工项） | 导出证据清单（待实现） |
