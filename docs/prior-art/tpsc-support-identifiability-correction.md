# 共享前缀的存在不等于必须动作相同

2026-11-14；这是候选命题的逻辑审计，不是新方法或机器人结果。
它补充[损失布局更正](tpsc-loss-fidelity-correction.md)，同样不能被写成“TPSC已得到数学创新”。

## 1. 一个遗漏的量词

令 \(V_A(s,H),V_B(s,H)\) 表示同一状态、给定动作窗口与剩余预算下，分别存在成功续接的当前动作片段集合。
集合必须相对于明确的任务谓词、动力学、预算和允许续接策略定义；本项目尚未估计出这些集合。

“允许共同前缀”意味着交集非空，但不意味着每对正确动作必须相同。
例如 \(V_A=V_B=\{-1,0,1\}\)，margin=0.5时，两个任务可共同选0，
也可分别选-1和1；后者同样正确且已满足分离要求。
因此“选出的两条示范共享前缀→任何分离都错误”这个推理不成立。

在有限集合中，若clean/control相同，分离与任务有效性存在必然冲突的条件是：

\[
\max_{a\in V_A,b\in V_B}\|a-b\| < m.
\]

这比“交集非空”严格得多；连续集合要处理supremum及能否取到的技术条件。
而且margin过大也会伤害不相交的窄集合，例如 \(V_A=\{0\},V_B=\{0.01\}\)，
m=0.5时仍无法由两条正确动作满足margin。因此这类冲突可能只是margin尺度失配，
不是特属于共享前缀的新机制。必须比较合适归一化、较小/校准margin等简单对照。

反过来，多模态有效集合也不支持强制相同输出：\(V_A=V_B=\{-1,1\}\)的两种动作可都正确，
均值0却可能不在集合内。shared support最多先说明允许共用，不能推出逐坐标一致性损失必然有益。
有限枚举的核算与断言保存在
[action-support-audit.json](../../experiments/so101/tpsc-loss-fidelity/action-support-audit.json)；集合是人为给定的逻辑例子。

## 2. 当前任务标签能证明什么

原manifest与脚本不改，但解释应收窄：

- `shared_prefix`证明的是脚本选择了相同的前段目标，不是所有成功策略必须相同。
- `no_common_prefix`当前是脚本较早选择不同接近路径；仅有不同目标物体并不能排除共同的短暂抬臂、张爪或停留。
  没有即时约束/预算/可行性证据时，不能将其当作“正确动作集合从第一步即不相交”的oracle。
- `multi_valid`是脚本路径族构造；运动学carry和错误TCP的IK没有证明这些路径均能物理成功。
- 当前左右branch的goal几何/RGB也随之改变；仍须同观测语言查询或固定双目标场景来隔离语义。

“最早分叉时刻”还必须区分：预测chunk第一次不同、实际执行第一次不同、示范的分叉时刻，
以及任务约束首次不允许共同续接的边界。它们不是同一个量，当前没有最后一种标签。
不能看到成功策略提前分叉就称其“过早纠偏”；可能只是另一条合法路径。

## 3. 直接改变实验判据

1. 先保证策略和物理任务能完成；载体失败不进入语义效应解释。
2. 动作距离只作诊断，不把偏离单一teacher前缀计为任务损害。
3. 对选定候选前缀，若要声称“共同正确”，需要两任务下分别成功续接的独立证据；
   这能验证这一候选前缀，仍不证明其他分离前缀都错误。
4. 统一分离的伤害要由匹配预算下的结果/可行性下降来验证，并排除margin、归一化、chunk窗口和执行能力等解释。
5. 普通BC、同池配对BC、多模态/阶段与适当margin对照若已解决问题，停止新方法主张。

本次更正进一步削弱了旧toy和脚本标签作为立项证据的力度。
TPSC仍是待否证的问题；尚无可冻结的核心创新，不因已经训练载体而保留它为必选方向。
